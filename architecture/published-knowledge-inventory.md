# Published knowledge inventory

Status: A15 accepted for approved local synthetic-data-only development under AM2. Independent review accepted the restricted scope; the residual availability finding remains unresolved and is a mandatory production security gate.

Metric `published_knowledge_inventory`, version `1`, owner BRI: count distinct governed, validated and published CSV knowledge records currently readable by the verified principal at one exact organisational node. This is the principal's authorized inventory, not an organisation-wide total or a completeness measure. There is no persistence, shared cache, historical replay, scheduled work, AI, hosted route or external connector.

## Contract

`GET /v1/reports/published-knowledge-inventory?scope_node_id=…` accepts one exact node parameter. The private, no-store JSON response separates result data from any request-specific metadata. A complete result contains metric ID/version, scope, `status: complete`, a count (possibly zero), and one evidence reference per record. Unavailable returns `status: unavailable` with neither count nor evidence. Authentication and authorization denials are separate; missing and inaccessible nodes are indistinguishable to otherwise eligible callers. Evidence carries a record ID, exact source-version ID, both digests and physical CSV line range. It never carries source bytes, extracted content or a storage path. Follow-through uses existing fresh authorization. Identical authorized inputs and parameters produce the same ordered result; previous disclosures are not recalled on revocation.

## Residual availability risk (A15-AM2)

Verification established logical tenant and exact-node authorization isolation, exclusion of hidden records from counts and evidence, and overflow based only on eligible records. Execution-budget failures fail closed: unavailable responses contain no count or partial evidence. The independent review identified no direct unauthorized count or evidence disclosure.

The approved-job scan can still examine hidden candidates before rejecting them. This can increase physical work and may change an observable complete response to unavailable when an execution budget is exhausted, even if authorized inputs have not changed. Completed verification did not demonstrate a hidden-row-induced timeout; it did not disprove the channel. The safeguards below limit execution or output in specific ways, not total memory or hidden-row influence. The finding remains unresolved. AM2 permits conditional risk acceptance only for local synthetic-data-only development and only with renewed independent sign-off.

**Mandatory production gate:** Do not use A15 reporting with real customer data or for hosted production execution until a separate production security assessment and approved risk treatment are in place. Assess realistic tenant and node cardinalities, distributions of hidden versus authorized records, query plans and authorization selectivity, inference through repeated requests, workload and resource isolation, appropriate mitigations, and testable production availability and security requirements. Future mitigation strategies are options, not approved implementation requirements. AM2 authorizes no reader redesign or database change.

## Protected read and budget

Migration 0032 adds one local-only reader operation under the existing restricted login. It uses the existing authoritative native-session and exact-node grant predicate. The publication joins, lineage checks and independent record/version allows mirror 0030 because that reader materializes extracted content across multiple nodes before callers can filter it. The existing reader remains unchanged. The exact-scope approved-job index supports ordered scanning; unique lineage keys prevent duplicate record counting. All decisions and returned evidence come from the same statement snapshot. The first 1,001 eligible identities distinguish a complete result from overflow; at most 1,000 compact rows may be transferred on success. Authorization precedes the logical bound. The API response ceiling is 512 KiB.

The trusted caller must arm a positive statement timeout of at most five seconds before the read. The function requires a finite temporary-file limit of at most 16 MiB, uses 1 MiB work memory per eligible operation, and disables parallel gather workers. Provision the temporary-file limit through the existing administrator-owned disposable cluster startup, not a parameter privilege for the reader. These are separate execution safeguards, not a universal per-query memory bound or proof that timing or resource-exhaustion channels are absent. Budget or integrity failure is unavailable, never a partial result. Stored evidence digests are returned without fetching or rehashing the underlying bytes.
