## Candidate contract (not acceptance)

Migration `0035_protected_unified_knowledge_search.sql` leaves prior migrations unchanged. It adds private helpers and two protected entry points, and existing forced-RLS tables receive scoped SELECT policies for the existing definer and named socket-only session. It neither provisions logins nor grants application access. The disposable fixture gives `bri_unified_knowledge_reader` execution of search and exact CSV evidence only; it has no direct table access. The isolated local API requires a private Unix socket, existing signed native identity verification with a synthetic provider transport, and a loopback HTTP boundary. Release routes are unchanged.

`POST /v1/knowledge/search` accepts one exact node and a literal query. Current native identity, tenant membership, exact-node authority, format-specific record and exact-version access, governed lineage, and current publication/validation are checked before protected content, logical limits and scoring in one statement snapshot. CSV uses source-scoped readable flags, not principal-targeted grants; XLSX uses both principal-targeted allows and latest publication. ASCII fold and whitespace normalization precede literal equality/substring matching. Exact matches precede substrings; ties use CSV before XLSX, then ascending record ID (the governed scope has one exact version per record), and earliest physical match within a record for the winning score. Results carry format, record and exact-version IDs, an excerpt with explicit ellipses on any clipped side, and either CSV inclusive first/last line or XLSX sheet ID and cell. Complete empty is distinct from unavailable without results. The logical limit is 1,000 eligible pairs combined with overflow detection; at most 20 results are returned, with 2,048-byte excerpts, a 256-byte normalized query and a 131,072-byte response bound. SQL prearms a 5 s timeout at the caller boundary and requires finite temp spill up to 16 MiB; 1 MiB work_mem is per operation, with parallel gather disabled. These are safeguards, not guarantees of fixed work.

Searchable values are individual CSV fields and canonical XLSX text cells, including validated headers. XLSX numeric, Boolean and calendar values are not coerced to text. There is no cross-field or cross-cell concatenation, wildcard or regex query interpretation, formula evaluation, or locale-dependent formatting. A search hit returns the exact IDs and typed match coordinates; the independently authorized CSV and XLSX evidence operations supply the format-specific provenance and digest metadata.

CSV span reconstruction starts at physical line 1, including the header. For each record, sum CRLF pairs (one break each) and remaining bare CR or LF separately in each canonical field; add to the start for the inclusive end; the next record starts at end plus one. The accepted extractor preserves embedded line breaks while unescaping quotes, rejects blank physical records, and does not count a terminal separator as a record. Mixed separators, BOM, and final-newline spelling do not affect the recurrence. AM1 compared 7,200 accepted synthetic variants against extractor spans and rejected three controls; identical canonical fields and overall range cannot yield different row spans under this contract. Search checks reconstructed bounds and digest consistency without reading quarantine bytes. `GET /v1/knowledge/csv/{record_id}/versions/{version_id}/evidence` explicitly checks tenant-qualified association and current authorization and returns document bounds and provenance digests, not a match selector. XLSX uses its existing exact-version evidence interface. Follow-through is fresh; missing, wrong-version and inaccessible evidence are not distinguished by response content. No previous hit grants access.

## AM5-R1 — versioned XLSX evidence and unified search contract

The AM5 stop finding above is historical. AM5-R1 authorizes a distinct local `GET /v2/knowledge/xlsx/{record_id}/evidence/{version_id}`. V1 keeps its strict response keys, serialization, pagination, and denial behavior; the accepted A16 client/parser are unchanged. V2 shares the existing staged reader, native authorization, exact-version SQL operation, scope/validation/publication and both access gates. It preserves the v1 record, version, node, worksheet, range, paged coordinates and cursor fields and adds `version: 2`, `source_id`, `original_sha256`, `canonical_sha256`, `extractor_version`, and `canonicalization_version`. No v2 field permits access to another version, and new v2 continuations are bound to v2 authorization and exact record/version. No new DDL, reader role, SQL entry point, privilege or policy serves this route. In `0033`, the tenant-qualified version-to-source foreign key enforces the documented common job UUID: the receipt's checked exact version UUID is also the governed source key, not the validated record UUID. V2 projects those already bound facts; it does not query source tables separately.

Search `POST /v1/knowledge/search` accepts a JSON object of exactly `scope_node_id` (exact node string) and `query` (literal text, 1–256 normalized UTF-8 bytes), using server-derived identity and tenant. An HTTP 200 is `{version: 1, status: "complete", results: [...]}` (empty array when no match); an unavailable HTTP 503 is `{version: 1, status: "unavailable"}` with no results. Routes use private, no-store. Each hit has `format`, `record_id`, `source_id`, `source_version_id`, `original_sha256`, `match` (`exact` or `substring`), `excerpt`, `excerpt_truncated`, `evidence`, and `evidence_url`. CSV adds `content_sha256`; its physical evidence is `{first_line,last_line}` and its link is the existing dedicated CSV exact-version operation. Its persisted source key is `csv:<UUID>` and its exact-version route ID is the UUID component of the persisted version key. XLSX adds `canonical_sha256`, `extractor_version`, and `canonicalization_version`; its evidence is `{sheet_id,sheet_title,cell}` and its link targets XLSX evidence v2. The 131,072-byte limit applies to the compact UTF-8 HTTP response, including metadata and the envelope. A response over budget is unavailable, not a reduced ranking. Match ordering, the combined logical allowance, and both AM2 access-first queries are unchanged.

Search includes validated headers and each individual canonical field/cell. XLSX searches canonical text, exact canonical number strings (including exponent notation), `true`/`false`, and canonical ISO date, time and datetime strings, using the existing ASCII/whitespace normalization and exact-then-substring scoring. Empty cells, unsupported types and serialization tags are not searched. There is no numeric equivalence, timezone assumption, reformatting or new extraction behavior.

The unchanged CSV fixture's four original controls are retained. Local acceptance uses the recovered native PostgreSQL 16.2 executables for the private PostgreSQL suites. The established verifier also uses the cached local container image for container-backed fixtures; the actual engine builds and fixture roles must be reported separately. The 16.16 CSV discrepancy remains open and must not be waived. Before any production deployment, independently qualify an actively maintained PostgreSQL version and resolve the test discrepancy without weakening the CSV reservation invariant. This decision selects no production database version.
