# A18-PREP — Unified governed knowledge search (proposal only)

Status: The preparation options below are historical. The A18.1 backend candidate and AM4 conditional local risk decision are tracked in [A18 backend and local risk](a18-backend-local-risk.md). A18.2, A18.3 and production use are not authorized.

## Current boundaries

CSV uses governed rows in shared source/version/extraction/validation tables and approved CSV jobs. The protected reader joins current record and exact-version allow rows keyed by source and version; those allows are not per-principal like XLSX. `csv_read_published` checks native/session and exact-node read authority per candidate, then returns wide extracted text across readable nodes. The A13 app layers bounded deterministic question/search projections over CSV, with physical line evidence. Its capped result is not a complete search candidate source. `0032` is exact-node CSV inventory, not term search, and has a documented residual physical availability channel.

XLSX uses separate immutable lineage, validation, latest publication revision, and separate principal-targeted record and exact-version allows. `0034` protects addressed record and worksheet pages, not enumeration or search. It carries sheet ID/title and physical cells/ranges, not CSV lines. Neither reader's publication or allow semantics should be homogenized. Existing detail and source follow-through stay protected, with an exact-version-aware adapter or endpoint where an existing route does not verify the requested version. Future PDF page positions are a contract extension only, with no PDF integration.

## Alternatives

A. Compose existing local protected readers in the application. Preserves existing grants and independent fresh decisions but XLSX has no search enumeration and CSV materializes across nodes before app filtering; bounded top-k over truncated results is not correct. Separate requests can observe different snapshots and cursor scopes; sequentially rechecking cannot make an atomic union. Hidden rows or saturated readers can still influence availability. No migration for simple composition, but a correct implementation needs new interfaces. Reject as the first slice as written.

B. One new protected read interface over existing stores (recommended). Apply both format-specific authorized relations in one consistent read snapshot with one server-derived principal, tenant and exact node. Authorization must gate ranking, logical work limits, selection and evidence materialization, not just the final projection. Verify execution plans; SQL predicate order alone proves no physical protection. Shared scoring and stable tie-breaks can yield a correct global result in one bounded request. No search pagination initially; a future cursor would require fresh checks and explicit snapshot/drift semantics. Requires an approved additive migration or other protected interface decision, named execution and narrowly authorized issuer visibility; no table grants, no existing function/ACL widening, no index assumed. Document any mirrored predicates and test parity. PDF could later implement another branch under separate approval. Moderate maintenance and a same-database deployment assumption.

C. Governed projection/index. Can reduce repeated scans and support pagination at scale, but requires new storage, write/rebuild and operational roles, tenant-qualified version keys, RLS or equivalent, atomic visibility/fresh final gates, deletion propagation, and explicit consistency targets. Reject stale document terms or provenance, including any use of withheld terms in corpus-wide ranking or counts. An index can still create availability and timing signals; it is not an authorization oracle. Higher migration, maintenance and deployment cost; defer until proven necessary. None of these options requires merging governance stores.

## Smallest useful local slice

Propose one explicit exact node and a bounded literal, deterministic search, no format picker. One result per authorized current record/version, with all branches using one documented scoring rule (start with binary literal token match and deterministic format/record/version tie-break; no corpus statistics), and a safe matched excerpt and typed evidence coordinate. Search only actual supported CSV cell text and XLSX text values, not serialization keys or package metadata. Specify normalization, token/size limits and cell/line mapping before coding. Return the bounded top set from a complete authorized evaluation and no totals. A legitimate zero-match response differs from unavailable when any branch cannot complete within the approved budget; do not silently return one format or partial rankings. No candidate IDs or denied format counts. Deny missing/inaccessible scopes generically; exact-node permission alone does not create record/version grants. Fresh evidence reads check identity, scope, publication, both allows, and exact version again; previously delivered data cannot be recalled.

Proposed local workspace tab and versioned read-only endpoint with no-store, exact route allowlists and inert content. No general catalogue, A13 question-answering extension, A15 metric change, reporting, semantic search, external AI, embedding or index. A15 inventory v1 stays CSV-only. Approve matching/ranking and pagination exclusion, candidate/decoded text and serialized output ceilings, timeout and memory/temp safeguards, bounded handling of dense workbooks, protected role/issuer/ownership design and evidence follow-through before implementation. A statement timeout is not a physical-work or memory bound. Hidden candidates must not consume the logical authorized allowance or influence successful results. Separately assess physical scanning and possible complete-to-unavailable differences; do not inherit A15's local risk acceptance or claim elimination of its channel. Stop if feasible physical limits require unapproved changes.

## Verification proposal

| Scenario | Required evidence |
|---|---|
| Tenant, siblings, session and exact-node authority | Disposable two-tenant fixtures with sibling nodes and restricted roles; deny spoofing, ancestor-only grant, revoked session/node, and missing versus inaccessible scope without metadata |
| Independent format gates | CSV only, XLSX only, both, neither; independent missing/denied record and exact-version allows for each format; approved but unreadable, and XLSX withdrawal. Verify CSV's existing publication/access semantics rather than inventing a CSV withdrawal event |
| Scope and snapshot | Concurrent access or publication changes cannot produce a mixed-state read; both branches and associated source versions from the same snapshot; reauthorize fresh requests |
| Ranking/count isolation | Hidden stronger matches never enter ranking, result selection or logical limits; no counts; stable scoring and tie order across repeated inputs; dense cell and CSV coordinate fixtures |
| Bounds and physical channel | Exact/over input, authorized work and output limits; representative hidden/visible distributions, execution plans, timeout/temp safeguards and repeated-request inference; unavailable with no partial results |
| Evidence and revocation | Wrong tenant/source/version and revoked record/version/publication deny fresh detail; verify CSV lines and exact XLSX sheet/cells, no raw storage paths; UI clears stale content |
| Compatibility and release | Independent authorization parity, forced RLS, ACL/catalog and hosted isolation, migration checksums/no-op if applicable; signed local API/workspace and regressions for A13 and A15 v1 |

Cross-format permission-filtered search is proposed, not delivered. Governed PDF remains deferred under the original MVP; any future PDF adapter requires qualified isolation, explicit resource contract approval and separate lifecycle authorization.
