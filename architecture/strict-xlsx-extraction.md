# Strict XLSX extraction (A16.1)

Status: accepted for local synthetic-only strict extraction. Independent review `deleg_fbfc2e08` passed implementation tree `8f717dd67ea8142906858754c31b10887cda1124`. The 59 XLSX tests and the disposable PostgreSQL 16.2 backend suite (676 tests, no failures, errors or skips) passed with exit 0. This is not governed intake or production approval. `extract_xlsx_strict(bytes)` is separate from `extract_xlsx`; the latter and its original-byte `content_sha256` semantics are unchanged.

## Supported package

The v1 profile is standard unencrypted XLSX with one visible worksheet and a text header in physical row 1. It accepts literal text, finite numbers, booleans, supported dates/times and empty cells. It rejects formulas including cached formulas, hidden sheets or rows/columns, merged cells, hyperlinks, external relationships, macros, embeddings, unsupported cell types and ambiguous/malformed structures. Formula-like literal strings are data, never executed.

Allowed package graph: `[Content_Types].xml`, `_rels/.rels`, `xl/workbook.xml`, `xl/_rels/workbook.xml.rels`, one `xl/worksheets/sheetN.xml`, optional `xl/styles.xml`, `xl/sharedStrings.xml`, `xl/theme/themeN.xml`, `docProps/core.xml` and `docProps/app.xml`. Only internal workbook, worksheet, styles, shared strings, theme, core-property and extended-property relationships are allowed, with matching content types. No stray parts or sheet relationship files. Bounded inert theme/properties and permitted presentation metadata do not contribute to canonical evidence. Formatting that explicitly selects a supported temporal type is semantic, not cosmetic.

## Resource limits

- ZIP: 5,000,000 original bytes; 256 entries; 10,000,000 actual inflated bytes per member; 25,000,000 overall; 100:1 expansion per member and overall. Stored/deflate only. Validate archive structure, normalized names, declared versus actual sizes and CRC. Decompress in memory; no extraction to disk and no re-opening unvalidated bytes.
- XML: hardened parser rejects DTDs, entities and external resolution; node/depth budgets apply before retention. At most 350,000 nodes and depth 32 per parsed part; inert metadata is separately capped at 256 KiB, 4,096 nodes and depth 16. Shared-string item and decoded/serialized byte budgets are enforced independently of the repeated-reference output budget.
- Worksheet: actual coordinates, not the declared dimension, determine bounds. Maximum 10,000 physical rows, 64 columns, 100,000 rectangular cells including nulls, and 100,000 physical cell elements including blanks. Each text value is capped at 4,096 UTF-8 bytes. Canonical output is at most 2,097,152 bytes.
- Linux subprocess: 2 seconds CPU soft limit and at most 3 seconds hard limit, 256 MiB address-space limit, 5 seconds parent wall deadline and bounded input/output transport. Limits may be lower if inherited. Failure, interruption, malformed output and timeouts yield no partial result. The worker is resource isolation, not a general filesystem or network sandbox; the parser has no workbook-directed external resource resolution.

## Canonicalization and evidence

Canonical v1 is compact UTF-8 JSON (no BOM or trailing newline), with keys ordered `rows`, `version`, `worksheet`. Rows are rectangular in ascending physical coordinate order, anchored at A1. Empty slots are `null`; non-null entries are `[type,value]` with tags `text`, `boolean`, `number`, `date`, `time`, `datetime`. An explicit empty string is text, distinct from a blank; styling alone does not anchor the rectangle. Every column in the rectangle must have a nonblank text header in physical row 1, starting at A1. For uniqueness only, compare stripped Unicode text after NFC normalization and case folding (then NFC again); the canonical frame retains the original parsed header text. Empty sheets and sheets that start after A1 are rejected.

Numbers come from bounded Decimal parsing of the stored lexical value, never binary floating point. Canonical zero is `0` including negative zero; nonzero values use a signed-if-negative, one-leading-digit mantissa with insignificant trailing zeroes removed and a base-10 exponent with no plus sign or leading zeroes. The adjusted exponent is at most 1024, and the normalized Decimal exponent (adjusted exponent minus fractional mantissa digits) is at least −1024. Date/time values use ISO representation without an inferred timezone. Both workbook epochs are supported; 1900 serial day 60 is rejected. Date-only serials cannot contain a fractional day and time-only serials must stay within one day. Supported serial fractions round to nearest microsecond, ties to even; rounding across midnight is rejected. Text preserves parsed Unicode and whitespace subject to XML semantics and the strict string profile.

Return immutable canonical bytes and evidence with the independent extractor and canonicalization versions, original SHA-256 over the exact incoming bytes, extracted SHA-256 over the canonical bytes, worksheet `sheetId`, title, and actual A1 range. The sheet ID identifies the worksheet only within the original digest's artifact. Neither internal package paths nor source-version or database record IDs are exposed. The parent validates the bounded canonical frame, including values and range consistency, without reparsing the original workbook. It trusts the isolated worker for the mapping from workbook bytes to physical coordinates and for input-specific checks such as raw numeric-token length. A future governed lifecycle must bind these fields to actual records and source versions, with its own privilege, retention, quarantine, review and publication approval.
