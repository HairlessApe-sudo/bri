# A19.2-AM2 signed Chromium recovery qualification

Use the same pinned local toolchain as the AM1 demo. Run from the repository root for the held reproduction, or from a frozen AM2 export (with the existing `.venv` and `web/node_modules` available) for the candidate run. Neither command connects to a hosted service or persistent database.

```sh
# Held AM1 reproduction: verifies the specific held tar against its Git tree,
# adds only the two named test drivers in a fresh private export, and verifies
# the correspondence again after the signed browser exits.
python -B scripts/a19_2_am2_held_export.py

# Candidate qualification, from the frozen AM2 export.
pg="$HOME/.hermes/cache/scratch/bri16.2.DGQrGAFq/pgserver/pginstall/bin"
node="$HOME/.hermes/tools/node-26.12.1-linux-x64/bin/node"
chrome="$HOME/.hermes/tools/chromium-1248/chrome-linux64/chrome"
swc="$HOME/.cache/next-swc/swc-linux-x64-gnu-16.4.6.tgz"
umask 077
env -i HOME="$HOME" PATH="${node%/*}:/usr/bin:/bin" TMPDIR="$HOME/.hermes/cache/scratch" \
  .venv/bin/python -B scripts/a19_2_am2_demo.py \
  --pg-bin "$pg" --node "$node" --chromium "$chrome" --swc-archive "$swc"
```

Record the exact export tree, command, output and exit code outside the export in a private evidence directory. Verify the final fixture-teardown line and the published screenshot manifest. Browser screenshots show only synthetic local fixture states; do not retain debugger traffic, login material, response headers, or DB snapshots. The CDP harness activates the actual DOM controls and attaches files; it does not claim mouse hit-testing coverage.

| Probe | Boundary |
| --- | --- |
| Held AM1 | Independent owner observes the committed, classified native job before corruption of the actual ASGI response. The real bridge emits no-store 502; the browser loses recovery. Reopening context and staging exactly the same file, metadata and node sends a new key and commits a second native job. |
| AM2 bridge 502 | Same fault boundary; no manufactured bridge response. The owner observes commit before release. |
| AM2 client receipt | The browser first receives the intact real no-store bridge 202. Only the page's upload caller receives a response with an additional JSON field. |
| AM2 transport loss | With commit independently observed, CDP aborts the real loopback bridge response at response stage; Chromium records a failed network request, not a synthetic status. |
| AM2 recovery and isolation | Both formats. Native committed command is bound to bytes, encoded metadata, exact node and idempotency key. The restricted fixture-side worker dispatches once; a manual UI retry returns the same job. Independent owner snapshots compare both job/audit tables, lineage, metadata and proposals; signed exact status is explicit. Browser-origin probes vary one authorized fingerprint field at a time and require 409 with no business write. |
| AM2 lifecycle | Normal receipt, concurrent submit/retry actions, definitive native wrong-media rejection, explicit abandonment (not cancellation), role/scope loss, signed identity replacement with a real held response, no observed automatic POST or status request, and no browser storage of recovery identifiers. Access, decisions and publication remain unchanged; a separately authorized signed search does not disclose the processed intake. |

Use the AM1 guide independently to qualify native decisions, publication/access prerequisites, and OFF behavior. These recovery drivers add no product endpoints, change no scopes in the product, and never use the browser to dispatch workers or publish content.
